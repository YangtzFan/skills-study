# Edge Browser Research 使用说明

通过用户授权的本机 Edge/Chromium 浏览器访问机构数据库、检索论文并验证下载。浏览器的登录配置跨项目复用，任务的页面恢复信息和检索进度保存在各自工作区。

本技能是一组供代理遵循的执行规则，需要宿主提供浏览器工具或可用的本地 CDP 能力；它不是浏览器扩展，也不包含独立的启动器或自动会话管理程序。技能不会自动登录，密码、MFA 和 CAPTCHA 由用户在浏览器中完成。

## 使用条件

本地浏览器模式需要已安装的 Edge 或可用的 Chromium、允许手动认证的图形桌面，以及代理可访问的本机回环调试端点。Chromium 替代时须明确说明并使用独立配置，具体按 SKILL 执行。默认检查 `http://127.0.0.1:9222/json/version`，控制浏览器前还要核对实例和配置归属；端口可连接不等于接入了正确的配置。

没有本地浏览器不影响独立的 [web-research](../web-research/SKILL.md) 通过可用工具执行公开搜索、静态网页读取或直接下载公开文件。只有需要本技能的认证或交互访问时，才要求相应浏览器能力。

优先复用已有且获授权的研究实例。需要新启动时，使用 [SKILL 中的操作系统启动示例](SKILL.md#connect-to-edge)。普通 Edge 窗口不一定启用了调试接口；不要为了接入调试而关闭无关窗口。

现有可选 helper 位于 `web-reader/scripts/edge_cdp.py`，依赖 Python 和已安装的 `websocket-client`，仅提供 `list`、`inspect`、`download`。导航、表单填写和按任务恢复仍由可用的浏览器工具或 CDP 操作完成，不存在 `restore` 等 helper 子命令。不要将 helper 输出直接当作可长期保存的任务档案。

## 配置与任务记录存在哪里

| 内容 | 位置 | 用途 |
| --- | --- | --- |
| Windows 专用浏览器配置 | `%LOCALAPPDATA%\CodexBrowser\EdgeResearch` | 保留浏览器偏好、Cookie 和登录状态，与当前项目无关 |
| Linux 专用浏览器配置 | `$XDG_CONFIG_HOME/codex-browser/edge-research`；变量未设置或不是绝对路径时使用 `$HOME/.config/codex-browser/edge-research` | 同一 Linux 用户跨项目复用，存在则复用，不存在则创建 |
| 当前任务恢复记录 | `<workspace>/.agents-work/<task-id>/browser/session.json` | 仅记录经过筛选的页面地址、题名、来源标识和检索进度 |
| 当前任务索引与证据 | 同一任务的 `index.md`、`downloads/` 等 | 登记文件用途、来源与验证结果，保留需要的下载 |

全局路径按运行浏览器的操作系统和用户解析。WSL/容器里的代理控制 Windows Edge 时，仍使用 Windows 用户的配置，不在 Linux 代理账号下再创建一份。不同系统或不同浏览器不共用一个正在使用的配置目录；Chromium 替代 Edge 时使用单独的 `chromium-research` 配置。

任务目录不保存浏览器配置、Cookie、密码、认证跳转地址或 Chromium `Sessions/` 文件。Chromium 自己的历史、缓存和内部会话数据仍可能留在全局配置中；这里分离的是任务恢复记录，不能保证消除所有浏览痕迹。

`.agents-work/` 是否被 Git 忽略按所在项目的约定检查，技能不自动修改忽略规则。任务档案不随技能代码暂存或推送。

## 新任务、继续任务与结束任务

| 场景 | 执行行为 |
| --- | --- |
| 新任务 | 在共享研究配置中创建独立空白窗口，不打开其他任务的页面 |
| 继续已有任务 | 使用原任务目录；先查找已确认归属的当前窗口，必要时只按该任务记录恢复页面 |
| 暂停或结束 | 保存当前任务的必要页面与进度；经授权后只关闭确认属于该任务的页面，保留全局配置 |

任务由当前请求和任务目录确定，不根据最后修改时间或碰巧打开的窗口猜测。运行时窗口/标签页 ID 只在当前实例中使用，不写入恢复记录；代理或浏览器重启后重新建立映射。归属不确定的窗口保持原状。

启动时不使用 `--restore-last-session`，专用配置的启动设置应为“打开新标签页”。`--new-window about:blank` 本身不能排除启动设置、管理策略或崩溃恢复额外打开旧页面，还要核对实际窗口。

不同任务窗口共享 Cookie、站点存储和部分浏览器设置，不能隔离不同账号。开始下载前重新指定本任务下载目录，避免文件落入上一个任务的目录；同一实例的并行下载需要协调。

## 给代理的请求示例

```text
使用 edge-browser-research，通过我授权的学校图书馆入口检索论文。
这是新任务，请创建独立空白窗口；密码或验证码由我手动处理。
```

```text
继续当前工作区 .agents-work/<task-id> 的任务。
优先复用该任务已打开的窗口；需要恢复时，只使用它的 browser/session.json。
```

```text
保存当前任务的页面与检索进度，然后只关闭这个任务的页面。
保留全局研究配置，供之后复用登录状态。
```

## 恢复、认证和论文访问

`session.json` 用 `navigate` 表示按已审核的稳定页面地址定位，用 `entry-and-search` 表示从安全的数据库入口重新检索。后一种记录通过唯一 `source_id` 关联检索词；参数不透明或包含认证信息的原地址不会直接保留。完整字段见[任务会话规则](references/task-sessions.md#task-record)。

页面地址不能恢复全部表单、POST 查询、滚动位置和浏览历史。恢复会产生正常的导航请求，并使用当前任务预算；它也不能延长网站的认证有效期。

若页面跳转统一认证，代理记录“需要重新认证”，由用户通过机构入口完成登录后继续。不会把认证地址写入任务记录，也不会因一个数据库失效就断言其他数据库同样失效。

验证结果应分别说明：选择了哪个配置、是否恢复了正确任务窗口、网站是否识别机构或账号、实际文章/文件能否访问、下载格式是否有效、全文能否读取。存在 Cookie 数据库、显示机构名或恢复了标签页，都不能替代其余检查。

## 常见情况

| 情况 | 处理方式 |
| --- | --- |
| 重启后仍出现旧任务页面 | 检查启动参数、专用配置的启动选项和崩溃恢复；只归档或关闭已确认归属且获准清理的页面 |
| 设置控件的 DOM 文本为空 | 通过正常 UI 或无障碍树核对选项标签及选中状态，不据此认定选项不存在 |
| 9222 被其他实例占用，或配置仍在使用 | 核对实例及配置归属，不删除锁文件、不启动同配置的竞争实例、不直接结束占用进程 |
| 页面能打开但下载找不到 | 检查本任务下载目录、浏览器下载历史、完成事件及实际文件；不要盲目重复点击 |
| Linux 没有图形桌面 | 报告无法进行手动认证的限制，或连接已有获授权的可达回环会话；不自动切换无头模式或添加 `--no-sandbox` |

## 已有验证与边界

2026-10-17 的 Windows 实机验证确认：全局配置迁移后可重新打开；去除恢复上次会话的参数后仅出现空白页面；从任务记录抽样定位两篇论文时，恢复窗口与新任务空白窗口分开，测试结束后可只关闭测试页面。

当次万方样本页面显示机构标识，IEEE 样本则跳转统一认证。此结果只描述当时的两个样本，不表示任意数据库或未来登录有效。Linux 已提供启动与路径规则，当前环境没有完成 Linux 实机验证。

结构和示例检查用于核对文档、字段及语法；真实权限、导航和下载仍须按实际任务验证。更新脚本时运行对应离线测试，更新启动或恢复规则时参考[验收场景](references/task-sessions.md#acceptance-checks)。
